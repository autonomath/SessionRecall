        How SessionRecall finds a chat

        Follow one search from the table, sqlite database backups, through each step. The numbers come from the index on the test Mac.

        1. Your words become a looser question

          6.6 asks its index for the three words as one exact phrase, in that order. Codex scans the chat files for that exact text in a prompt or reply, and checks the titles for all three words in the same order. SessionRecall asks its index for the phrase or any one of the words, and lets the last word also match longer words that start with it, so results appear while you type. Accents are ignored, so cafe also finds café.

          6.6 asks

          "sqlite database backups"

          No chat contains that exact phrase, so 6.6 shows nothing.

          Codex asks

          "sqlite database backups" in a prompt or reply, or a title with sqlite … database … backups

          No prompt or reply contains that text, and one other chat's title fits, so Codex shows that one.

          SessionRecall asks

          "sqlite database backups" OR "sqlite" OR "database" OR "backups" OR backups*

        2. It reads the whole chat, one part at a time

          6.6 keeps a sample of each chat, up to 48,000 characters with all parts mixed together. A long chat loses most of its text, and tool output loses the most. Codex reads prompts and replies in full but never looks at tool calls or tool output. SessionRecall indexes everything, with a separate index for each part of a chat. Tool output is indexed without keeping a second copy of the text.

          Text 6.6 searches272 MB Text SessionRecall searches2.9 GB

          SessionRecall's index on the test Mac, by part: tool output 604 MB, replies 120 MB, tool calls 119 MB, your prompts 75 MB. Titles are matched from the list in memory, so a renamed chat is found under its new name right away.

        3. Rare words count more

          Each match is scored with BM25, the standard scoring formula of search engines. A word found in few chats says more about a chat than a word found in hundreds, and a word counts more in a short prompt than lost in a long one. Here is how many of the 4,390 chats with prompts use each word in their prompts:

          backups77 sqlite150 database277

          So "backups" in a prompt counts for much more than "database". In tool output, "database" appears in 3,119 chats, so a match there counts for little.

        4. Where it matched matters

          Each score is then multiplied by the weight of the part it came from, and a chat's scores are added up. What you typed yourself is the best clue to what a chat was about; tool output is mostly logs and file contents. Because rarity is counted first, an exact rare phrase in tool output can still beat a common word in a title. 6.6 ranks nothing: it lists every match newest first. Codex puts title matches before text matches and orders each group by how closely the words fit.

          Title×4 Your prompts×3 Replies×2 Tool calls×1 Tool output×0.6

          The backups chat comes first: its title and its prompts have "database" and "backups", and "sqlite" turns up in its tool output. Chats that match only "database", or match only in tool output, score lower.

        5. One row per chat, with the reason

          Codex Desktop writes a long chat as several files sharing one id; 12 of the last 326 chats on the test Mac are split that way. SessionRecall merges them into one row at the file that matched best. A sub-agent chat counts toward the chat that started it, at half weight. Each row shows which part matched and the passage around the words: prompts and replies come straight from the index, and tool output is read from the chat file for the top 30 results.

        6. It opens on the match and says what it can't see

          Opening a result waits until the whole chat is loaded, turns on Tools when the word is in tool output, and scrolls to the word. 6.6 could jump while only the end of a long chat was loaded and stop short. A chat you are still writing is read from its file at search time, so new text is found about 20 seconds after it is saved; 6.6 waited until the chat had been quiet for two minutes, and up to 45 minutes for large files. Chats SessionRecall cannot read yet are counted, never dropped silently:

          4 not fully indexed yet | 4 updating | 150 with parts too large to index

        What it costs

        • A larger index: 1.11 GB on the test Mac, up from 431 MB. Tool output is 604 MB of it, and Settings can leave tool output out.
        • One reindex after installing, in the background. Search keeps answering from the old index meanwhile, and memory held at about 2.5 GB.
        • Sub-agent chats fold into the chat that started them, which moves three of the 28 private searches down one or two places. Settings can list them as separate rows instead.

        Install

        Download SessionRecall 1.0.1

        • Open the disk image and drag SessionRecall to Applications. It is signed with a Developer ID and notarized by Apple.
        • It needs macOS 14 or later, on Apple silicon or Intel.
        • Updates arrive inside the app, from the project's releases on GitHub.
        • Coming from Agent Sessions? Quit it first. Both apps keep their index in the same folder, so run one at a time. Settings start fresh.
